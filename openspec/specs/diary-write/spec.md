# diary-write Specification

## Purpose

한 줄 다이어리 작성 및 최근 기록 조회 기능을 제공한다. 사용자가 오늘 날짜를 자동으로 확인하고, 한 줄 텍스트를 저장하며, 최근 저장된 기록을 목록으로 볼 수 있게 한다.

## Requirements

### Requirement: 오늘 날짜 자동 표시
시스템은 화면 로드 시 오늘 날짜를 `YYYY-MM-DD` 형식으로 자동 표시해야 한다(SHALL).

#### Scenario: 페이지 로드 시 날짜 표시
- **WHEN** 사용자가 페이지를 로드한다
- **THEN** 시스템은 오늘 날짜를 `YYYY-MM-DD` 형식(예: `2026-12-31`)으로 화면에 표시한다

### Requirement: 한 줄 입력 및 저장
시스템은 한 줄 텍스트 입력 필드와 저장 버튼을 제공해야 하며(SHALL), 저장 버튼 클릭 시 입력된 텍스트를 오늘 날짜 및 저장 시각과 함께 기록으로 저장해야 한다(SHALL).

#### Scenario: 텍스트 입력 후 저장
- **WHEN** 사용자가 입력 필드에 한 줄 텍스트를 입력하고 저장 버튼을 클릭한다
- **THEN** 시스템은 오늘 날짜, 저장 시각, 입력한 텍스트를 하나의 기록으로 저장하고 목록에 반영한다

#### Scenario: 같은 날 여러 번 작성
- **WHEN** 사용자가 같은 날짜에 두 번째 텍스트를 입력하고 저장 버튼을 클릭한다
- **THEN** 시스템은 기존 기록을 덮어쓰지 않고 별도의 새 기록으로 추가 저장한다

#### Scenario: 빈 입력값 저장 시도
- **WHEN** 사용자가 입력 필드가 비어 있는 상태에서 저장 버튼을 클릭한다
- **THEN** 시스템은 빈 기록을 저장하지 않는다

### Requirement: localStorage 기반 영속 저장
시스템은 저장된 모든 기록을 브라우저의 localStorage에 보관해야 하며(SHALL), 페이지를 새로고침해도 기존 기록이 유지되어야 한다(SHALL).

#### Scenario: 새로고침 후에도 기록 유지
- **WHEN** 사용자가 기록을 저장한 후 페이지를 새로고침한다
- **THEN** 시스템은 새로고침 이전에 저장된 모든 기록을 다시 불러와 표시한다

### Requirement: 최근 기록 목록 표시
시스템은 저장된 기록을 최신순으로 정렬하여 목록으로 표시해야 하며(SHALL), 기본으로 최근 5개가 보이고 5개를 초과하는 기록은 스크롤을 통해 확인할 수 있어야 한다(SHALL).

#### Scenario: 기록이 5개 이하인 경우
- **WHEN** 저장된 기록이 5개 이하이다
- **THEN** 시스템은 저장된 모든 기록을 최신순으로 목록에 표시한다

#### Scenario: 기록이 5개를 초과하는 경우
- **WHEN** 저장된 기록이 5개를 초과한다
- **THEN** 시스템은 목록 영역에서 최신 기록이 상단에 오도록 표시하고, 스크롤을 통해 5개를 초과하는 이전 기록도 확인할 수 있게 한다

### Requirement: 기록 인라인 수정
시스템은 목록의 각 기록 항목에 수정 버튼을 제공해야 하며(SHALL), 수정 버튼 클릭 시 해당 항목의 텍스트를 입력 필드로 바꿔 수정할 수 있게 해야 한다(SHALL). 저장 시 해당 기록의 텍스트만 갱신해야 하며(SHALL), 날짜 및 저장 시각(정렬 기준)은 변경하지 않아야 한다(SHALL).

#### Scenario: 수정 버튼 클릭 시 인라인 편집 진입
- **WHEN** 사용자가 목록의 한 항목에서 수정 버튼을 클릭한다
- **THEN** 시스템은 해당 항목의 텍스트를 입력 필드로 표시하고 저장/취소 버튼을 보여준다

#### Scenario: 수정 내용 저장
- **WHEN** 사용자가 인라인 입력 필드의 텍스트를 변경하고 저장 버튼을 클릭한다
- **THEN** 시스템은 해당 기록의 텍스트를 새 값으로 갱신하고, 날짜·저장 시각은 그대로 유지하며 목록에서의 순서를 바꾸지 않는다

#### Scenario: 수정 취소
- **WHEN** 사용자가 인라인 편집 중 취소 버튼을 클릭한다
- **THEN** 시스템은 텍스트를 원래 값으로 되돌리고 인라인 편집을 종료한다

#### Scenario: 빈 값으로 수정 저장 시도
- **WHEN** 사용자가 인라인 입력 필드를 비운 상태에서 저장 버튼을 클릭한다
- **THEN** 시스템은 기록을 갱신하지 않고 인라인 편집 상태를 유지한다
